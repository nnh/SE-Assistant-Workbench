# 統計解析スケジュール管理

試験ごとの統計解析作業のスケジュールを、Google スプレッドシートのタイムライン表示（ガントチャート）で管理するためのツールです。
試験一覧に LPO とデータロック日を入れると、作業（SDTM作成、ADaM作成、TLF作成など）の行が自動で追加され、人日・人月で指定した期間から開始日・完了日が計算されます。
LPO やデータロック日を変更すると、作業の日付も自動で再計算されます。

## シート構成

| シート | 内容 | 入力 |
|---|---|---|
| README | このドキュメントへのリンク | 自動作成 |
| 試験情報マスタ | 研究管理システムから取り込んだ試験情報（プロトコルID、試験名、研究種別、状態、FPI、LPO、登録開始、登録終了、中間用データ固定、追跡終了） | 自動取り込み（編集不可） |
| 試験一覧 | 略称、表示状態、LPO、データロック、備考 | 手入力 |
| 作業テンプレート | 作業、基準、順番、標準期間、単位 | 手入力（初期値あり） |
| スケジュール | 略称、作業、回、基準、順番、期間、単位、開始日、完了日、警告 | 略称〜単位は手入力、開始日〜警告は自動計算 |
| イベント一覧 | イベント名の一覧 | 手入力（初期値あり） |
| イベント | 略称、イベント、回、日付 | 手入力 |
| タイムライン用データ | タイムライン表示の元データ | 自動生成（編集不可） |

## 初回設定

1. Apps Script エディタの「プロジェクトの設定 → スクリプト プロパティ」で、スクリプトプロパティ `RESEARCH_SYSTEM_URL` に研究管理システムのURLを設定してください。
   - 未設定のまま「初期設定」を実行すると、ダミー値が登録され、設定を促すメッセージが表示されます。
2. スプレッドシートを開き直し、メニュー「スケジュール管理 → 初期設定」を実行します（初回は Google の承認画面が表示されます）。
3. 試験情報マスタの A1 セルに「アクセスを許可」が表示されたらクリックします（初回のみ）。
4. タイムライン表示を作成します。
   1. タイムライン用データシートの A:D 列を選択し、「挿入 → タイムライン」を実行します。
   2. タイムラインの設定を次のようにします。

      | 設定 | 列 |
      |---|---|
      | カードのタイトル | 作業 |
      | 開始日 | 開始日 |
      | 終了日 | 終了日 |
      | カードの色 | 略称 |
      | グループ | 略称 |

## 使い方

### 試験を登録する

1. 試験一覧に行を追加し、略称・LPO・データロックを入力します。
   - 略称は試験情報マスタのプロトコルIDから選べます。マスタにない略称も入力できます（警告表示のみ）。
2. LPO とデータロックの両方が入ると、作業テンプレートの作業がスケジュールシートに自動で追加されます（基準・順番・期間・単位はテンプレートの値）。
3. 必要に応じて、スケジュールシートで試験ごとに基準・順番・期間・単位を調整します。

### 作業の日付の計算方法

- 期間は 1人日 = 1営業日、1人月 = 20営業日 として日数に換算します（端数は切り上げ）。
- 基準は「〇〇前」「〇〇後」の形で指定します。〇〇には LPO、データロック、イベント一覧のイベントを選べます。
  - 〇〇前: 基準日の前営業日から、順番の大きい作業から逆算して詰めます。同じ順番の作業は完了日を揃えて並行して進めます。
  - 〇〇後: 基準日の翌営業日から、順番の小さい作業から前向きに詰めます。同じ順番の作業は開始日を揃えて並行して進めます。
- LPO とデータロックは試験一覧の日付、それ以外のイベントはイベントシートの同じ試験・同じ回の日付を基準日にします。
- 基準日が未入力、期間が不正な作業は日付が空欄になります。
- 「〇〇前」の作業と「LPO後」の作業がデータロック日以降にかかると、警告列に「データロック日を超過」と表示されます。

### イベントを入力する

イベントシートに略称・イベント・日付を入力します。中間解析のように複数回あるものは「回」を入力します。
イベント一覧にないイベントも入力できます（警告表示のみ）。ただし、作業の基準に使えるのはイベント一覧にあるイベントだけです。

### 試験を非表示にする

試験一覧の表示状態を「非表示」にすると、その試験はタイムラインに表示されず、スケジュール・イベントシートの行も隠れます。

### 更新のタイミング

試験一覧・作業テンプレート・スケジュール・イベントのいずれかを編集すると、作業の追加・日付の計算・タイムライン用データの更新が自動で行われます。
自動で更新されない場合は、メニュー「スケジュール管理 → 表示を更新」を実行してください。

### タイムラインの色

タイムライン用データの背景色が、タイムライン表示のカードの色になります。作業は白、イベント（LPO・データロックを含む）は淡いピンクです。

## 制限事項・注意点

- 営業日は土日のみを除いて数えます。祝日は考慮していません。
- 人日・人月は 1人が専任で担当する前提で換算しています。担当人数や兼務率は考慮していません。
- 作業テンプレートを変更しても、既にスケジュールシートにある行には反映されません（新しく追加される行にのみ使われます）。
- 自動で行うのは作業の行の追加だけです。試験一覧から試験を削除したり略称を変更したりしても、スケジュール・イベントシートの行は削除されません。
- 「初期設定」は、既に内容があるシートのデータを上書きしません。イベント一覧を変更したときは、基準の選択肢に反映するため「初期設定」を再実行してください。
- 試験情報マスタでは、研究管理システムの状態が Completed・Stop・No Support の試験は取り込みません。

## 開発

[ASIDE](https://github.com/google/aside)（TypeScript + clasp）で構成しています。

| ディレクトリ・ファイル | 内容 |
|---|---|
| `src/index.ts` | エントリポイント（onOpen、onEdit、メニューから呼ぶ関数） |
| `src/constants.ts` | シート名・列・初期値などの定数 |
| `src/schedule-logic.ts` | 日付計算などのロジック（GAS API に依存しない） |
| `src/formula-builder.ts` | 試験情報マスタに書き込む数式の組み立て |
| `src/sheet-service.ts` | スプレッドシートの読み書き |
| `test/` | Jest のテスト |

```bash
npm install
npx clasp login
npm test
npm run deploy
```

- `npm run deploy` は lint・テスト・ビルドのあと、`.clasp-dev.json` のスクリプトにプッシュします。本番環境へは `npm run deploy:prod`（`.clasp-prod.json`）でプッシュします。
- `.clasp-dev.json`・`.clasp-prod.json` は Git 管理対象外です。
